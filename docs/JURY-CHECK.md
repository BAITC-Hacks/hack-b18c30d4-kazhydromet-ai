# Проверка жюри: запуск и маршрут на 5 минут

Кейс Freedom «Граф денег», команда Kazhydromet AI. Нужны Git, Python 3.12+ и `uv`.
Установка выполняется один раз; пятиминутный маршрут ниже начинается после запуска.

## 1. Запуск на Windows

Репозиторий **закрытый (private)**, выдан платформой хакатона. Для клонирования
нужен GitHub-аккаунт с предоставленным доступом; войдите под ним до запуска команды.
HTTP 404 без входа или без доступа не означает, что проект удалён.
Инструкция организаторов не требует делать репозиторий публичным.

```powershell
git clone https://github.com/BAITC-Hacks/hack-b18c30d4-kazhydromet-ai.git kazhydromet-ai
cd kazhydromet-ai
uv venv .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
.\run.ps1
```

Оставьте терминал открытым. Приложение: <http://127.0.0.1:8000>; остановка — `Ctrl+C`.
Если порт занят: `.\run.ps1 -Port 8012`, далее замените 8000 на 8012 в адресах.
Для macOS/Linux используйте команды раздела «2. Быстрый старт» в [README](../README.md).
Расчёт и экран работают без ключа; интернет нужен для первоначальной установки пакетов.

## 2. Автоматическая проверка — первая минута

Полная проверка CSV и API одной командой: `.\.venv\Scripts\python.exe scripts\verify.py`.
Ожидается 21 + 24 проверки с кодом 0; результат — `out/verification.json` с выводом,
версией кода и контрольными суммами. Скрипт запускает и останавливает свой сервер 127.0.0.1:8013.

Во втором терминале, из корня того же клона:

```powershell
.\.venv\Scripts\python.exe scripts\check_outputs.py
.\.venv\Scripts\python.exe scripts\smoke_api.py
curl.exe http://127.0.0.1:8000/api/health
```

Ожидается **21/21 OK**, код завершения **0**; health возвращает `"ok": true`.
Валидатор проверяет сохранённые CSV и свежий пересчёт, включая лимит 300 секунд.
В `out/nodes_roles.csv` — 2 248 клиентов; `clusters.csv` — 72 кластера; `top_nodes.csv` — 50 строк.
`smoke_api.py` использует стандартную библиотеку и собственный временный сервер
на `127.0.0.1:8013`, затем сам останавливает его. Скрипт не читает `.env`, очищает
ключи в окружении сервера и проверяет локальный чат без внешней модели.
При занятом порте выберите другой:
`.\.venv\Scripts\python.exe scripts\smoke_api.py --port 8014`.

## 3. Три контрольных клиента — две минуты

Вставьте полный gid в поиск и нажмите Enter. Те же факты доступны через `GET /api/node/{gid}`.

| gid | Что должно быть в карточке |
|---|---|
| `100000008603629100` | Кандидат в организаторы, №5; получил 1 817 300 ₸ от 19 клиентов, отправил 4 986 156 ₸ 61 клиенту. |
| `100000000332284100` | Признаки консолидации, №17; флаг дробления: 10 из 12 входящих переводов, 10 плательщиков. |
| `100000003037476100` | Признаки консолидации, №583; получил 555 000 ₸ от 3 клиентов; исходящие **неизвестны**, обрыв четвёртого колена. |

У первого клиента нажмите «Потоки по дням», переместите шкалу и запустите воспроизведение.
Дата, суммы и направленные связи меняются по реальным переводам; «Весь период» возвращает месяц.
API календаря: `GET /api/timeline/100000008603629100` — 31 день; неизвестный gid возвращает HTTP 404.

## 4. Решение аналитика и AI — две минуты

Добавьте первых двух клиентов в «Перечень на проверку», откройте его в шапке и скачайте Markdown.
В файле должны быть именно эти два gid, обоснования, карточки и запросы недостающих сведений.
Экспорт: `GET /api/report?gids=100000008603629100,100000000332284100` — HTTP 200, Markdown-вложение.
Для автоматического списка: `GET /api/top?n=20` и `GET /api/report?top=20`.
Печатный отчёт: `GET /api/report/view?gids=100000008603629100,100000000332284100`.
Кнопка «Печать / сохранить PDF» открывает печать браузера; Markdown API сохранён.
HTML-эндпоинт принимает `top` от 1 до 100 или до 100 разных `gids` через запятую.
В перечне блок «Что даёт этот перечень» считает охват без повторов; «Добавить» увеличивает его на указанное число новых переводов. API: `/api/review-coverage?gids=...`.
В чате нажмите «Объясни роль клиента»: ответ должен опираться на числа и показывать вызовы инструментов.
Проверьте также «Что произошло 23 июля у 100000008603629100?» (`daily_transfers`)
и «Какой охват перечня и кого добавить?» (`review_scope`, при выбранном перечне).
У агента восемь инструментов. `POST /api/chat` по-прежнему принимает `messages`;
опциональный `context` содержит `selected_gid`, `selected_date` (`2026-07-DD`)
и `review_gids` (до 100 строковых gid). Явные gid и даты вопроса важнее контекста.
Без `OPENAI_API_KEY` на сервере или при сбое API используется локальный `mock`; это не ответ внешней модели.
Живой режим требует серверного ключа и доступа к API. `health.live` означает готовность настроек, не успешность запроса.
Запасной экран: <http://127.0.0.1:8000/graph.html>. Данные, роли и API у обоих экранов общие.

**Все роли, аномалии и маршруты — гипотезы для проверки, не доказательство вины. Решение принимает человек.**
