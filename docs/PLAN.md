# План: «Граф денег» (кейс Freedom)

ТЗ целиком: [docs/case/TZ.md](case/TZ.md). Подсказки и ловушки от организаторов: [docs/case/STARTER.md](case/STARTER.md).
Данные: `data/raw/*.parquet` (2 248 узлов, 3 119 рёбер, 4 840 транзакций, июль 2026).

## Одной фразой
AML-аналитик знает 81 «курьера». Инструмент по их исходящим переводам на 4 колена строит граф,
назначает каждому узлу роль с объяснением в цифрах и ранжирует, кого проверять первым.

## Must have (без них решение не засчитывается)
1. Один запуск: сырые parquet → 3 CSV за < 5 минут: `python -m app.pipeline`.
2. Все 2 248 узлов получают `role`, `role_score`, `cluster_id`, `priority_score` и `evidence` (с числами, ≤ 200 символов).
3. Правило с порогом для каждой роли, записанное в README. На любой gid жюри объясняем за минуту.
4. Кластеры: `clusters.csv` (cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis).
5. `top_nodes.csv` ≥ 20 строк + экран со схемой сети: направление потоков, цвета ролей, поиск по gid.

Роли: consolidator, transit, distributor, terminal, coordinator, peripheral. Можно добавить свою,
например `truncated` (обрезан 4-м коленом), но её надо описать в README.

## Критерии оценки (100)

Ценность 15 · Оригинальность 10. README весит столько же, сколько код.

## Ловушки (их учёт оценивается)
- 444 узла на 4-м колене без исходящих — это обрыв обхода, а не «деньги осели». Не называем их terminal вслепую.
- У seed занижены входящие суммы, поэтому out/in у них бессмыслен (бывает 20+). Seed оцениваем по исходящим.
- Сумма и количество переводов — разные сигналы, учитываем оба.
- Граф направленный. Louvain (неориентированный) используем только для кластеров и прямо это оговариваем.
- 19 seed без рёбер тоже должны попасть в выгрузку (роль peripheral, evidence «нет переводов ≥ 5 000 ₸ в выгрузке»).
- Формулировки только как гипотезы: «признаки консолидации», а не «организатор».

## Архитектура
```
data/raw/*.parquet → app/pipeline.py (метрики → правила ролей → кластеры → приоритет)
                   → out/nodes_roles.csv, out/clusters.csv, out/top_nodes.csv, out/graph.json
FastAPI (app/main.py) → /api/graph, /api/node/{gid}, /api/top, /api/clusters, /api/chat
web/index.html → схема сети (vis-network, CDN) + топ-лист + карточка узла + чат с агентом
Агент (OpenAI Agents SDK) → инструменты над графом: карточка узла, кто кому платит, пути между узлами
```

## Контракт бэк ↔ фронт (меняем только через STATUS.md)
- `GET /api/graph` → `{"nodes": [{"id": gid, "role", "cluster", "priority", "is_seed", "depth", "label"}], "edges": [{"from", "to", "sum_kzt", "n_tx"}]}`
- `GET /api/node/{gid}` → строка nodes_roles + `in`/`out`: списки контрагентов `{gid, sum_kzt, n_tx, role}`
- `GET /api/top?n=50` → строки top_nodes.csv
- `GET /api/clusters` → строки clusters.csv
- `POST /api/chat` — прежний контракт.

Пока бэк не готов, фронт работает на `out/graph.json`: Ali выложит его первым.

## Тайминг (ориентир)
- **+1:00** — pipeline выдаёт 3 валидных CSV (пусть с грубыми правилами), фронт рисует граф из graph.json.
- **+2:30** — правила ролей отточены, эндпоинты готовы, фронт подключён к API.
- **+3:30** — опциональные фичи: временной транзит 1–2 дня, устойчивость при удалении топ-N, AI-ассистент.
- **+4:15** — фриз фич. README, ship-check, чистый клон, прогон демо.
- **Последний час** — все в зале, выходить нельзя.

## Опциональные фичи (по убыванию выгоды)
1. Отделение обрезанных 4-м коленом от настоящих конечных получателей (учитывается отдельно).
2. Временные паттерны: пришло и ушло за 1–2 дня, синхронные переводы нескольких плательщиков в один день.
3. AI-ассистент: «кто собирает деньги с этих пятерых?» → ответ по графу со ссылками на gid (у нас уже есть агент).
4. Устойчивость: что станет с крупнейшей компонентой, если убрать топ-N узлов.
5. Карточка узла и «что запросить дальше» (оценка полноты).

## Нельзя
Хардкодить gid, выдавать «чёрный ящик», додумывать атрибуты клиентов, требовать GPU или платные сервисы.
