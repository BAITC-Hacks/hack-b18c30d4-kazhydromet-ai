# Ревью пайплайна и запросов к графу

Проверено по `docs/case/TZ.md` (разделы 5, 7, 9, 10), `docs/PLAN.md`, коду и `out/nodes_roles.csv`. Роли ниже — гипотезы, а не признаки виновности.

## Баги и исправления

1. `app/pipeline.py:164–175` — проверка `consolidator` идёт до `truncated`. У трёх узлов 4-го колена evidence говорит «отдал дальше 0%», хотя исходящие из них не выгружались. Пример — первый gid ниже. Оставить роль по нескольким входящим допустимо, но убрать вывод об удержании денег и явно написать про обрыв в evidence.
2. `app/graph.py:118–126` — `common_receivers([g, g])` считает один gid двумя отправителями; ответ `reached_from=2` содержит два одинаковых `from`. Удалить повторы входных gid до обхода и считать число уникальных источников.
3. `app/graph.py:132–146` — `money_path` строит путь по месячным агрегатам без проверки дат. В данных есть маршрут, где переводы первого ребра начались 20.07.2026, а все переводы второго завершились 19.07.2026: вывод «деньги дошли» неверен. Строить пути по отдельным транзакциям с неубывающими датами или называть ответ структурной связью, не маршрутом денег.
4. `app/graph.py:93–97` — `/api/top` не возвращает поле `why` из `top_nodes.csv` вопреки контракту в `PLAN.md`; при фильтре по роли `rank` начинается заново с 1 (первый `terminal` в API — №1, в общем рейтинге — №205). Вычислять глобальный `rank` до фильтра и `why` через `pipeline.why` для всех узлов.
5. `app/graph.py:88–90` — `graph_json()` читает файл без `_state()`: если запустить сервер до построения `out/`, первый `/api/graph` завершается ошибкой. Инициализировать выгрузки через `_state()` перед чтением. Узлам `graph.json` также не хватает `label`, обязательного в контракте `PLAN.md`; добавить его при генерации (`app/pipeline.py:351–355`).
6. `app/agent.py:121–127` — `_mock()` при любых двух gid отвечает об общих получателях, даже на вопрос «покажи путь от A до B»; без ключа демонстрационный ответ не соответствует запросу. Для вопроса о пути вызывать `graph.money_path`; в остальных случаях явно указывать, какой запрос выполнен.

## Что объяснить жюри

- `app/pipeline.py:140–206`: порядок правил задаёт единственную роль при смешанных признаках. На 4-м колене входящий сбор может быть виден, а дальнейшее движение неизвестно. Разобрать на карточке узла альтернативные признаки и ограничения.
- `app/pipeline.py:152–203`: `role_score` — вручную заданная сила правила, не статистически проверенная вероятность: размеченных ролей нет. Так и подписать в README/UI; для роли `transit` с неполными входящими не обещать высокую уверенность.
- `app/pipeline.py:273–285`: приоритет — относительный рейтинг текущих 2 248 узлов (процентиль метрик и нормировка на максимум), а не оценка риска или виновности. При новом графе те же суммы дадут другой балл; формулу и множители seed/truncated показать рядом с топом.
